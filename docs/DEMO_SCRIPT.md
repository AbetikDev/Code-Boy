# Code Boy demo recording script

Use the installable `code-boy-1.0.10.vsix`. The demo project is `demo/discount-bug`; its threshold test is intentionally failing until Bob IDE fixes the example. Do not show `.env` or access tokens in the recording.

1. Install `code-boy-1.0.10.vsix` in VS Code with **Extensions → … → Install from VSIX…**. Open `demo/discount-bug` as the workspace folder (not the repository root) and reload if VS Code asks. Open the Code Boy Activity Bar view. Make a few saved small edits in `src/cart.cjs`; show **Stats → Coding**, **Craft**, and **Project health**. A single large paste can be shown separately: Code Boy calls it assisted editing without claiming authorship.
2. Open a **new integrated terminal** in that workspace and run `npm test`. The threshold test fails: expected 90, actual 100. Show the red ContextBack thread and Code Boy's concern. If no red thread appears, enable `terminal.integrated.shellIntegration.enabled`, close the terminal, open a new one, and run the test again. Ensure `contextBack.trackTerminalCommands` is enabled. Avoid running the test in an external terminal; ContextBack listens to VS Code's terminal shell execution events.
3. In VS Code, run **Code Boy: Resolve Blocker with Bob** from the Command Palette. Review the modal and click **Copy Prompt**. Open the **same** `demo/discount-bug` folder in Bob IDE, use Agent mode, and paste the prompt. Ask Bob to inspect the repository, explain the threshold defect, make the focused fix, and run `npm test`. The Code Boy command copies a prompt; it does not launch Bob IDE itself.
4. Show Bob IDE's actual diff and passing test. In Bob IDE chat, open **Tasks**, select this task, then click its **task header** to display the task session consumption summary. Save a PNG screenshot in the repository's `bob_sessions/` folder with a distinct name such as `codeboy_task03_discount_blocker_summary.png`. The [IBM guide](https://lablab-ibm-bob-2-hackathon-guide.s3.us.cloud-object-storage.appdomain.cloud/index.html) requires these screenshots. Return to VS Code, reload the changed file if prompted, rerun `npm test` in its integrated terminal, and show the same test blocker disappear and Code Boy react.
5. End on the Developer State panel and mention that edit counts and health signals stay local; ContextBack's optional diff review is a separate feature.

Capture the recording continuously enough to establish **failing test → Bob IDE edit → passing test**. The existing screenshots in `bob_sessions/` show earlier Bob test tasks and do not prove this particular demo. Reset the demo fixture after recording if the repository should keep the reproducible blocker.

Suggested voiceover: “Returning to a project, I see the current test blocker instead of reconstructing it from memory. Code Boy tracks editing patterns and project health without guessing who wrote the code. I hand the blocker to Bob IDE, let Bob inspect and fix the repository, then rerun the test. ContextBack sees the same blocker resolve.”
